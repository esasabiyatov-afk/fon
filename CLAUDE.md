# Fon — контекст проекта для Claude

## Что это
Личное iOS-приложение: обёртка над m.youtube.com, чтобы слушать музыку с YouTube в фоне на iPhone (как Background Play в Brave). Только для себя, не для App Store. Общение с владельцем — на русском.

## Ограничения окружения (важно)
- **Mac нет.** Владелец на Windows. Xcode локально недоступен.
- **Сборка — только в облаке:** `.github/workflows/build.yml` на `macos-15-intel` (arm64-машины GitHub бывают перегружены — сборка отменялась, не дождавшись runner): XcodeGen → `xcodebuild` без подписи (версия `1.<run_number>`, build `<run_number>`) → `Fon.ipa` в Artifacts (`Fon-ipa`) **и в Releases** (тег `build-N`, вместе с `apps.json`). `apps.json` — источник SideStore: `https://github.com/esasabiyatov-afk/fon/releases/latest/download/apps.json`; по нему SideStore показывает обновления Fon. Работает, только когда репозиторий публичный (он публичный). Сборка запускается на каждый push в `main` (только main; правки `*.md` сборку не запускают) и вручную (workflow_dispatch); новая отменяет незаконченную старую (`concurrency`), а публикация пропускается, если в Releases уже есть сборка новее.
- Проект Xcode **не хранится** в репозитории — его генерирует XcodeGen из `project.yml`. Новые `.swift` в папке `Fon/` подхватываются автоматически. Не создавай `.js`-файлы в `Fon/` (Xcode может положить их в Compile Sources) — JS живёт строками в `Scripts.swift`.
- **Установка на телефон:** iloader (Windows) с бесплатным Apple ID, подпись живёт 7 дней. Sideloadly с конца октября 2026 не работает (ошибка Apple -80046).
- **Продление (с 27.10.2026):** владелец перешёл на SideStore (установлен через iloader) + LocalDevVPN из App Store; вход в Apple ID в SideStore заработал после выбора anisette-сервера «SideStore (New)» и Reset adi.pb. Fon ставится в SideStore через «+» из скачанного IPA; автопродление — автоматизация «Команд» (Refresh All).
- Проверить на настоящем айфоне можно только руками владельца — проси скриншоты и описание поведения.
- Логи GitHub Actions могут быть недоступны для чтения из облачной сессии; при ошибке сборки проси владельца скопировать текст ошибки.

## Архитектура
| Файл | Роль |
| --- | --- |
| `Fon/AppDelegate.swift` | `AVAudioSession .playback`; `SceneDelegate` (там же) создаёт окно с `MainViewController`. Сцены нужны, чтобы окно на iPad растягивалось на весь экран (`UIRequiresFullScreen` убран) |
| `Fon/MainViewController.swift` | Лента: **свой WKWebView на каждую вкладку** (создаётся лениво, не перезагружается при переключении; повторное нажатие — наверх, затем к корню). Своя панель вкладок `TabBarView` (системный `UITabBar` на iOS 26 рисовал иконки выше своей границы — они налезали на мини-плеер): **Главная · История · [Музыка/Видео] · Подписки · Вы** (порядок владельца, 28.10.2026; переключатель режима — в центре). «История»: видео — `/feed/history`, музыка — «Недавно слушали» (нативный список). Вкладки «Поиск» на панели нет: поиск — отдельное место в той же области (`searchTabIndex = tabs.count`), открывается лупой в шапке YouTube или лупой на подборках. В режиме музыки «Главная» → нативные подборки `MusicHomeViewController` (лента YouTube с чипом «Музыка» — по карточке, флаг `musicFeedShown`; повторное нажатие «Главной» возвращает к подборкам), «Вы» → «Медиатека» (`LibraryViewController`); оба — `UINavigationController` дочерними VC в `browseContainer`. Перемешивание/очередь из своих треков — `/watch_videos?video_ids=…` (до 50 id). `PlayerView` поверх; уход в фон, прерывания (звонки) |
| `Fon/Settings.swift` | `Settings.musicMode` (UserDefaults `musicMode`, по умолчанию вкл.) — общий для плеера и вкладок |
| `Fon/PlayerView.swift` | Отдельный WKWebView со страницей `/watch`. Режимы: мини-полоска (64pt над вкладками) и развёрнутый. В режиме музыки развёрнутый = нативный `MusicPlayerView` поверх веб-плеера (webview играет под ним); кнопка «список» показывает страницу YouTube, ♪ — назад к плееру. В режиме видео: шапка с ♡ (сохраняет видео в «Понравившиеся» режима музыки — облачный плейлист), PiP и ♪. Свайп вниз по видео/обложке (`UIPanGestureRecognizer`, плеер едет за пальцем) сворачивает; в полном экране — выходит из него (видео тоже едет за пальцем с сопротивлением). Мини-полоска тянется вверх за пальцем. **Мини-плеер режима видео — маленькое окно с видео в правом нижнем углу над вкладками, как в приложении YouTube (1.79):** 210 pt на iPhone, 340 pt на iPad, скругление 10, ⏸ снизу слева и ✕ сверху справа на тёмных кружках, нажатие/вверх — развернуть, вниз — закрыть; лента под ним без отступа. **Автоматическая «картинка в картинке» при выходе на домашний экран убрана** (была в 1.79–1.80: на выходе из неё плеер застревал — видео съезжало, страница не отвечала; владелец: «убирай»); PiP — только кнопкой в плеере. Страница плеера, выгруженная iOS из памяти, грузится снова (`webViewWebContentProcessDidTerminate`); скрытые вкладки — только когда их откроют (`terminatedViews`). **Жалоба после 1.78: лента посреди прокрутки грузится заново с начала** — это iOS выгружает открытую страницу из памяти, а мы перезагружаем её; теперь при предупреждении о нехватке памяти (`didReceiveMemoryWarning`) скрытые вкладки освобождаются (адрес — в `parkedURLs`, загрузятся при открытии), чтобы iOS не трогала открытую; «Главная»/«Подписки» режима видео — свои ленты, им это не грозит. **Мини-плеер режима музыки — как в Apple Music (1.78):** плавающая карточка со скруглением 14 над вкладками (отступы 8 pt, `MainViewController.miniPlayerFrame`), справа ⏭ вместо ✕, **закрыть — смахнуть вниз** (`handleMiniDrag`); в режиме видео — полоска с ✕, как было. Выбранная вкладка в режиме музыки красная (`TabBarView.selectedColor`), на главной крупный заголовок «Главная» вместо приветствия. В мини-полоске ♡ (`miniLikeButton`, просьба владельца после 1.69) — в «Понравившиеся», как ♡ в плеере. Плавность (просьба владельца): скорость пальца при отпускании (`takeReleaseVelocity`) передаётся пружине `setPlayerState(_:velocity:)` (0,5 с, damping 0,86), возврат на место — пружиной со скоростью пальца, сопротивление как у прокрутки iOS (`rubberBand`) |
| `Fon/MusicPlayerView.swift` | **С 1.78 — дизайн Apple Music** (просьба владельца: «версию айфона тоже как Apple Music, только обложка с видео»): фон — размытая обложка (`backdrop` + `systemThickMaterialDark`, до загрузки — градиент), сверху «язычок» `chevron.compact.down` и «откуда играет» мелко, название слева (21 semibold) и исполнитель (19, серый) с ♡ справа, крупные ⏮ ▶ ⏭ без белого круга, громкость, **нижний ряд: повтор · режим видео · AirPlay (`AVRoutePickerView`) · очередь («Далее»)**; `panelHeight` 304. Ранее — плеер в стиле Spotify: обложка 16:9 без чёрных рамок (`ArtworkLoader` размер `.player`; ширина = ширина панели, высота — по пропорции, `art = min(pw, space * aspect)`),  градиент под её средний цвет; **с системным плеером на месте обложки — его видео** (файл 360p всё равно качается; `AVPlayerLayer` `resizeAspectFill` в рамке обложки, появляется по `isReadyForDisplay`; в фоне отключается — иначе iOS ставит плеер с картинкой на паузу; просьба владельца после 1.66); **нажатие на обложку/видео** (`videoToggleTapped`, `Settings.videoArtwork`) — видео ↔ просто обложка (просьба владельца после 1.69; кнопку в углу убрали в 1.72), ♡ (облако), **свайп обложки влево/вправо — следующий/предыдущий трек** (`artworkSwipe`, только горизонтальный — вертикальный сворачивает плеер; просьба владельца после 1.69), ползунок (плавно интерполируется между сообщениями: обновление 20 раз/с, мелкие расхождения с плеером <0,4 с не поправляются рывком — после 1.89 он шёл ступеньками и отпрыгивал; **у системного плеера с 1.92 ползунок читает настоящее время AVPlayer** (`NativeAudio.displayTime`, 20 раз/с, только чтение) — без угадывания: угадывание ехало вперёд, пока поток подгружался, и отпрыгивало назад; во время перемотки показывает выбранное место, перемотка точная (`toleranceBefore/After: .zero` — иначе прыжок к ключевому кадру видео); жалоба «ползунок всё ещё глючит» после 1.91), prev/play/next, повтор трека (`video.loop`) |

## Ключевые приёмы
- **Безопасная область (просьба владельца: «везде знать про чёлку»):** ничего управляемого под «чёлкой»/Dynamic Island и у полоски «домой». Полный экран — видео на весь экран (вариант 1.56 с `bounds.inset(by: safeAreaInsets)` уменьшал видео — владельцу не понравилось), а панель YouTube `#player-control-overlay` — внутри safe area: `PlayerView.sendSafeArea` → `__fon.setSafe` → CSS `--fon-safe-*`; развёрнутый плеер, мини-полоска и `browseContainer` — в пределах safe area слева/справа (альбомная ориентация). Шапки своих экранов уже отступают `safeAreaInsets.top`.
- **Системный плеер (AVPlayer)** — см. `NativeAudio.swift` и `DirectStream.swift` в таблице: с 1.64 работает напрямую, с 1.65 включён по умолчанию.
- **Видимость:** `document.hidden`/`visibilityState` всегда «visible», события `visibilitychange` перехватываются на window (capture) и не доходят до YouTube; настоящее состояние — `__fon.realHidden`.
- **Автопродолжение в фоне (как Brave `MediaBackgroundingScript.js`):** `HTMLMediaElement.prototype.pause/play` обёрнуты — пауза из JS **при видимой странице** = пауза пользователя (`__fonUserPaused`); в фоне пауза из JS YouTube не считается пользовательской (обычно это реакция на отказ WebKit), настоящая пауза в фоне — только наша команда (`fon.explicitPause` → `__fonHardPause`). Пауза без JS (от WebKit при сворачивании) + переход в hidden в пределах 2 с → вызываем оригинальный `play()`.
- **Старт в фоне (видео ещё грузилось при сворачивании):** без звука iOS усыпляет приложение и WebKit, видео не стартует. `PlayerView.watchBackgroundStart` держит `beginBackgroundTask` и зовёт `__fon.backgroundTick(first)` **сразу**, затем раз в 0,5 с (до 25 с; раньше первый вызов был через 1 с — отсюда пауза ~1 с при сворачивании) — вызов `evaluateJavaScript` будит WebKit, страница жмёт `play()`; следим все ~25 с фоновой задачи (стоп раньше — только 'idle', пауза пользователя); **в 1.52 отпускали после 3 тиков (~1 с) — пауза от iOS приходила позже, музыка останавливалась (жалоба владельца)**. **Смена трека в фоне:** за <6 с до конца трека (тик раз в 1 с) и на `ended` страница шлёт `{type:'trackEnding'}` → `MainViewController.keepAliveUntilPlaying()` (то же, что при сворачивании); `backgroundTick` не считает почти доигравший трек «playing», а если через 3 с после `ended` YouTube сам не переключил трек — жмёт `cmd('next')`. Отключение наушников (`routeChange .oldDeviceUnavailable`) → `markUserPaused`, чтобы не включить звук в динамик.
- **Своя громкость YouTube** (просьба владельца: музыку тише, чтобы слышать игру): ползунок под кнопками в `MusicPlayerView` → `Settings.youtubeVolume` → `NativeAudio.setVolume` (`AVPlayer.volume`). **Работает только у системного плеера** (проверено владельцем в 1.62 — музыка тише) — с веб-плеером ползунок скрыт. У веб-страницы на iPhone громкость не меняется ничем: `video.volume` заблокирован, Web Audio не берёт звук потока MediaSource (1.52), служебный `_setMediaVolumeForTesting:` WebKit не действует (1.56). Вариант «спрятать MediaSource, чтобы YouTube отдал простой поток, и пропустить его через Web Audio» владелец отклонил.
- **Звук при открытии:** плеер открывается не нажатием на его странице, поэтому YouTube считает это автозапуском и включает видео muted. В `player` на `playing`/`volumechange`/тик раз в секунду вызываем `movie_player.unMute()` + `video.muted=false` (WebKit позволяет — `mediaTypesRequiringUserActionForPlayback = []`). Если muted случился в пределах 1,5 с после касания страницы — это пользователь (`__fonUserMuted`), не трогаем. Не больше 5 включений за 10 с.
- **Экран блокировки:** Now Playing ведёт сам WebKit через `navigator.mediaSession`. `setActionHandler` перехвачен: наши play/pause/nexttrack/previoustrack/seekto, `seekforward/seekbackward = null`, YouTube их не перезапишет. Нативного `MPRemoteCommandCenter` нет — он конфликтовал с WebKit.
- **Лента → плеер:** клик по `a[href]` с путём `/watch` в ленте перехватывается и уходит в плеер (`{type:'open'}`); запасной путь — KVO на `url` ленты. В плеере ссылки не на `/watch` уходят в ленту (`{type:'browse'}`).
- **Шапка YouTube (логотип, поиск, ⋮) в окне плеера прячется под нашей верхней панелью** (просьба владельца после 1.71): окно страницы сдвинуто вверх на высоту шапки (`PlayerView.pageHeaderHeight`: 48 pt, дальше её уточняет страница — `{type:'header'}` раз в 1,5 с; на iPad может отличаться). **Стилями шапку убирать нельзя** (так было в 1.72: `display:none` + `ytm-app{padding-top:0}` + `#player-container-id{top:0}`) — прилипающие блоки страницы (чипы «Все видео/Автор…») считают отступ от шапки+плеера, и над ними оставался зазор 48 pt, сквозь который виднелась прокрутка (скриншот владельца).
- **Видео в рамке обычного плеера** (скриншот владельца после 1.80: картинка больше окна, съехала вправо поверх названия — YouTube оставил старые размеры после окна мини-плеера/PiP): вне `fon-mini`/`fon-full` `#player-container-id .html5-video-container` и `video.html5-main-video` прибиты к 100% рамки (только главный плеер, чтобы не задевать превью в рекомендациях) (`object-fit: contain`); при входе в мини и выходе — `resize` + `repaint` (после 1.81 окно мини-плеера бывало чёрным).
- **Мини-режим:** класс `fon-mini` на `<html>` растягивает `#player-container-id/.player-container/#player` и `video` на весь viewport; webview в мини-полоске 16:9.
- **Из режима музыки в видео** (веб-плеер, iPad): `fon.setMusic(false)` перерисовывает видео через 0,4 и 1,5 с — WebKit терял картинку после долгого `opacity: 0` (жалоба после 1.78: «видео не идёт, только обложка, звук идёт»; не проверено).
- **Режим музыки / экономия:** класс `fon-music` прячет `video` (opacity 0) и показывает обложку `i.ytimg.com/vi/<id>/hqdefault.jpg`; качество — минимальное через `movie_player.setPlaybackQualityRange/setPlaybackQuality`. В фоне качество тоже падает до минимума (кроме PiP). YouTube запоминает качество в `localStorage['yt-player-quality']` — из-за этого 144p «прилипало»; теперь в режиме видео ключ стирается в начале документа, а после понижения качество явно ставится в hd720 (iPhone) / hd1080 (iPad). Чистый «только звук» в веб-плеере невозможен (протокол YouTube), это осознанный компромисс.
- **Режим музыки — контент:** видео открывается с Mix-плейлистом `&list=RD<id>` (похожая музыка, как радио в YT Music); под плеером скрыты комментарии и Shorts.
- **Свой полный экран:** m.youtube на iPhone включает системный AVKit-фулскрин (без субтитров YouTube и меню качества). В `player` подменены `webkitEnterFullscreen/requestFullscreen/exitFullscreen` и геттеры `fullscreenElement/fullscreenEnabled/webkitDisplayingFullscreen`: класс `fon-full` растягивает плеер на окно, шлются `webkitbeginfullscreen/fullscreenchange`, приложение получает `{type:'fullscreen'}` — прячет шапку и статус-бар, на iPhone поворачивает в landscape (`requestGeometryUpdate`), но вертикальное видео (`videoHeight > videoWidth`) оставляет в portrait. В полном экране качество не понижается и видео видно даже в режиме музыки. **Полный экран, правки после 1.71 (просьба владельца по скриншотам):** (1) сверху — **своя полоса `FullscreenBar`** в `PlayerView` (кнопка выхода ⤡ и название видео на затемнении, в безопасной области, касания принимает только кнопка): показывается вместе с панелью YouTube — страница шлёт `{type:'controls', shown}` (раз в 250 мс смотрит, видна ли кнопка паузы/полного экрана; не нашла — 3,5 с после касания); (2) **⋮ рядом с кнопкой полного экрана скрыт** (в вертикальном полном экране ничего не делал): **в `player-fullscreen-controls` прячутся только блоки с миниатюрами (`img` шире 40 px)** — в 1.73–1.78 элемент прятался целиком, но на iPad в нём все кнопки полного экрана («в полном экране кнопок нету», жалоба после 1.78) (после 1.72 на скриншоте ⋮, подсказка «Другие видео» с миниатюрой поверх кнопки выхода и полоса похожих видео внизу остались — это допы полноэкранной панели YouTube; время/ползунок/⚙/субтитры/пауза в других элементах) и запасной путь `fullControls()` ищет кнопки в правом нижнем углу панели — «полный экран» по классу `fullscreen-icon`/подписи, а не нашла — это предпоследняя кнопка угла, ⋮ — последняя; (3) выход по касанию **и по координатам кнопки** (цель касания могла быть прозрачным слоем), подписи «полноэкран…/свернуть/minimize». DOM вертикального полного экрана из облака не получить (плеер не поднимается) — если выход всё равно не работает, ⤡ в нашей полосе работает независимо от разметки YouTube. **Выход кнопкой YouTube** (жалоба владельца: «кнопка свернуть не работает» — YouTube снова просил «войти»): пока `fon.isFull`, нажатие на видимую кнопку полного экрана (`.fullscreen-icon` или aria-label «полноэкран…/fullscreen») перехватывается в capture-фазе (click; запасной путь — касание без сдвига, через 350 мс) → `setFull(false)`.
- **iPad, полный экран без кнопок (жалоба после 1.82, третий раз):** вероятная причина — наши «уборки» (`tidyFullscreen` поднимался от «Другие видео»/ряда «Нравится» до общего блока, `hideFullscreenThumbs`, `hideMoreButton`) прятали блок вместе с кнопками плеера. Теперь прятать можно только блок без кнопок плеера (`safeToHide`: нет паузы/ползунка/⚙/полного экрана/времени (`CORE`), не больше 5 кнопок); уже спрятанные такие блоки раз в 1 с возвращаются (`unhideCore`); ⋮ — только с подписью «ещё/more/…» или без подписи. Не проверено.
- **Пропадающая картинка видео (чёрный экран, звук идёт):** WebKit теряет слой видео после перестроек страницы (меню ⚙, поворот, выход из полного экрана). `fon.repaint()` убирает видео на 2 кадра (`display:none`) и возвращает, а на это время рядом с видео кладёт снимок текущего кадра (`canvas`), чтобы не было заметного мигания (жалоба владельца после 1.29); вызывается при смене полного экрана, возврате в приложение, повороте (`viewWillTransition`), а **только в полном экране** — по `MutationObserver` на class/style/детей `body` и class `html` (меню YouTube) и после `touchend` (в обычном плеере это мигало на каждое касание). После своей перерисовки 1,2 с мутации игнорируются (без зацикливания). В полном экране скрыта «Фоновая подсветка» (cinematics). Меню YouTube (`bottom-sheet-container` и др.) в полном экране подняты поверх плеера (z-index). Пока меню YouTube открыто (скрипт шлёт `{type:'menu', open}`; проверка на касаниях и при добавлении элементов, не чаще 4 раз/с), свайп вниз плеера выключен **только на самом меню** (скрипт шлёт `top` меню; меню считается открытым, лишь если оно сверху — `elementFromPoint`) — иначе, потянув меню ⚙, владелец выходил из полного экрана; а ложное «открыто» отключало свайп выхода совсем (жалоба владельца). После выхода из полного экрана повторный вход 1,5 с не принимается (YouTube мог сразу запросить его снова). **Субтитры** в полном экране — по центру ширины, на 20% мельче (`scale(0.8)`, просьба владельца после 1.83); в вертикальном полном экране (под видео ≥70 px) — сразу под картинкой (класс `fon-cap-below`, `--fon-cap-top`).
- **Компактный список в режиме музыки** (просьба владельца после 1.69: «мелкими значками, больше результатов»): окна вкладок получают первым скриптом `window.__fonList = <режим>` (`MainViewController.browseScripts`; при смене режима скрипты окон пересобираются и вызывается `__fon.setList`), `browse` ставит класс `fon-list` → `ytm-video-with-context-renderer`/`ytm-compact-radio-renderer`/`ytm-compact-playlist-renderer` строкой: обложка 16:9 112×63 (у `hq*.jpg` 4:3 `object-fit: cover` в рамке 16:9 ровно обрезает чёрные полосы), без аватара канала, длительности и значков, название в 2 строки. Вёрстка m.youtube проверена в Chromium (Playwright, iPhone-UA) скриншотами. В режиме видео — обычный YouTube.
- **Главная в режиме музыки:** грузится `/#fon-music`; скрипт `browse` убирает хэш и нажимает чип «Music/Музыка» (`ytm-chip-cloud-chip-renderer`) — обычные рекомендации, но только музыка.
- Скрываем родную нижнюю панель m.youtube (`ytm-pivot-bar-renderer`).
- **Порядок в полном экране:** ряд «Нравится/Не нравится/Поделиться/Сохранить» и «Другие видео» наезжали на время и главу — `tidyFullscreen` (раз в 1 с в полном экране) ищет их по aria-label/тексту в `#player-control-overlay`/`#player-container-id` и вешает класс `fon-hidden-full` (скрыт только при `html.fon-full`).
- **Зависшая загрузка** (после долгой паузы в свёрнутом приложении крутился спиннер): сторож раз в 1 с — должно играть (`!paused` или состояние 3), а `currentTime` стоит: 6 с → `seekTo` на то же место, 12 с → `loadVideoById` с этой секунды, 20 с → перезагрузка страницы с `t=`.
- **Плавность прокрутки (просьба «оптимизацию ещё лучше», после 1.80):** `ArtworkLoader` распаковывает JPEG в фоне (`preparingForDisplay`), а не на главном потоке при первом показе; своя лента видео подгружает обложки заранее (`prefetchDataSource`) и при новой странице вставляет только новые карточки (`insertItems`, без `reloadData`).
- **Обложки:** при сбое сети (нет ответа) `ArtworkLoader` повторяет запрос ещё 2 раза через 1,5 с.
- **Кэш (просьба владельца — «не грузить заново»):** обложки — память (`NSCache`, 500) + диск `Caches/artwork` (имя — SHA1 ключа, JPEG; при запуске старше ~1500 файлов удаляются), одна загрузка на картинку (ожидающие ячейки ждут её); `URLCache.shared` 64 МБ / 512 МБ; «Понравившиеся» — `Caches/likes.json` (видны сразу при запуске); подборки — `Caches/music-feed.json`. Страницы YouTube кэширует сам WebKit (`WKWebsiteDataStore.default()`, размер не настраивается). **Видео кэшировать нельзя:** YouTube отдаёт поток кусками через MSE (googlevideo, свой протокол), WebKit их не хранит, а перехватить https-запросы в WKWebView невозможно.
- **Ссылки в плеере:** в основное окно уходят только каналы/поиск/плейлисты/ленты (`BROWSE_PATH` в `player`); остальное (ответы в комментариях и т. п.) YouTube обрабатывает сам — владелец жаловался, что «Другие ответы» не открывались.
- **iPad (правки после 1.74, просьба «исправь всё»):** карточки каруселей ×1,3; строки списков («Рекомендации», «Новое») — читаемая ширина до 760 pt по центру (и в веб-списке `max-width: 760px`); число плиток пересчитывается при смене ширины (`viewDidLayoutSubviews` → `reload`). **Форма обложек — прямоугольник 16:9 везде** (просьба владельца после 1.71: «это же YouTube — не квадраты, всё строится с учётом этого»): карточки подборок (`large` 240 pt, `small` 190 pt шириной), сетка «Быстрый доступ» (2 колонки, 4 карточки; iPad — 3×2), строки (`RowCell`, `TrackCell` медиатеки, «Далее», `VersionCard`), мини-плеер (`miniArtwork` 16:9), плеер, лента YouTube. **Круглыми остались только аватары исполнителей** (как у каналов YouTube). Новые обложки — только 16:9. Ячейки запоминают ключ картинки ДО загрузки (картинка из кэша приходит синхронно — иначе «Мой микс» и др. оставались пустыми).
- **Форма обложки и видео в музыкальном плеере — оригинальная** (просьба владельца после 1.83: «вертикальное — вертикально, квадратное — квадратом»): `ArtworkLoader` для `.player` обрезает тёмные поля превью со всех сторон (`trimmedArtwork`: строки/столбцы без точки ярче 40 на уменьшенной копии 96 px; осталось <20% или форма вне 0,45…2,2 — обычная 16:9; ключ кэша `…-player-orig`); `MusicPlayerView.applyAspect` — рамка по форме видео (`presentationSize` системного плеера), когда видно видео, иначе по форме картинки. Списки, карточки и мини-плеер — по-прежнему 16:9.
- **Дата выхода видео везде** (просьба владельца после 1.81: «на главной, в рекомендациях — везде»): в новой вёрстке m.youtube под карточкой бывает только «канал • просмотры», дата — лишь в `aria-label`. `common` (`addDates`, вместе с проверкой Shorts раз в 1,5 с) дописывает « • N дней назад» в строку с просмотрами карточек без даты (`DATE_RE`: «… назад», «… ago», «Трансляция/Премьера…»; до 4 попыток на карточку). Свои ленты (`videoFeed`, `collectVideos` → «Подписки», лента музыки, экран исполнителя) берут дату из частей строки, иначе из `accessibilityText/Label` (`dateOf`). **Нет даты и в `aria-label`** (рекомендации под видео — скриншот после 1.83): `common` сам спрашивает YouTube **без cookies** (`credentials: 'omit'`, клиент WEB, `hl: ru`): `youtubei/v1/next` текущего видео — даты всех похожих (`lockupViewModel` → части «… назад»; проверено из облака: 20 из 20), а для прочих видимых карточек — `next` каждой (`relativeDateText`), не больше 2 запросов сразу, кэш `dateCache` (пусто — больше не спрашивать). `player` не годится: из облака LOGIN_REQUIRED без `microformat`.
- **Перевод комментариев, как в приложении YouTube** (просьба владельца после 1.83): `player` раз в 1,5 с (если есть комментарии) под комментарием не на русском (кириллицы < 50% букв) ставит «Перевести на русский» (`.fon-translate`); нажатие — `translate.googleapis.com/translate_a/single?client=gtx&sl=auto&tl=ru&dt=t` прямо со страницы (CORS `*`, проверено из облака), текст заменяется, после перевода надпись «Показать оригинал (переведено Google)», как в приложении YouTube (скриншоты владельца), ещё нажатие — оригинал (возвращается исходная разметка). Комментарий — `ytm-comment-renderer`/`ytm-comment-view-model`/`ytm-comment-reply-renderer` (самый внутренний), текст — `.comment-text`/`#content-text`/…, запасной путь — самый длинный абзац не из шапки. Селекторы m.youtube не проверены (из облака страница видео — капча).
- **Ник канала кириллицей** YouTube иногда показывает закодированным («@%D0%A1…», скриншот после 1.81): `common` (`decodeHandles`, раз в 1,5 с, XPath по тексту с «@%») раскодирует.

## Как работать
0. **Не собирать без команды (с 28.10.2026):** правки коммитить и пушить только в рабочую ветку `claude/…`; в `main` (= сборка и новая версия в SideStore) — только когда владелец скажет «собирай». Тогда все накопленные правки уходят одной версией. **Отдельную проверку компиляции на ветке (`workflow_dispatch`) после каждой правки НЕ запускать** (просьба владельца 29.10.2026): код проверит сборка по «собирай»; если она упадёт — исправить и собрать снова. JS по-прежнему проверять локально `node --check`.
1. Правки → проверка JS: вырезать строки из `Scripts.swift` и прогнать `node --check`; логику можно гонять в jsdom со стабами `play/pause/visibilityState/mediaSession`.
2. Коммит и push в `main` → дождаться зелёной сборки в Actions → дать владельцу ссылку на run (Artifacts → Fon-ipa).
3. Владелец ставит через iloader поверх старой версии и присылает результат.
