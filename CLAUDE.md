# Fon — контекст проекта для Claude

## Что это
Личное iOS-приложение: обёртка над m.youtube.com, чтобы слушать музыку с YouTube в фоне на iPhone (как Background Play в Brave). Только для себя, не для App Store. Общение с владельцем — на русском.

## Ограничения окружения (важно)
- **Mac нет.** Владелец на Windows. Xcode локально недоступен.
- **Сборка — только в облаке:** `.github/workflows/build.yml` на `macos-15-intel` (arm64-машины GitHub бывают перегружены — сборка отменялась, не дождавшись runner): XcodeGen → `xcodebuild` без подписи (версия `1.<run_number>`, build `<run_number>`) → `Fon.ipa` в Artifacts (`Fon-ipa`) **и в Releases** (тег `build-N`, вместе с `apps.json`). `apps.json` — источник SideStore: `https://github.com/esasabiyatov-afk/fon/releases/latest/download/apps.json`; по нему SideStore показывает обновления Fon. Работает, только когда репозиторий публичный (владелец согласился сделать его публичным 27.10.2026). Сборка запускается на каждый push в `main` (только main; правки `*.md` сборку не запускают) и вручную (workflow_dispatch); новая отменяет незаконченную старую (`concurrency`), а публикация пропускается, если в Releases уже есть сборка новее.
- Проект Xcode **не хранится** в репозитории — его генерирует XcodeGen из `project.yml`. Новые `.swift` в папке `Fon/` подхватываются автоматически. Не создавай `.js`-файлы в `Fon/` (Xcode может положить их в Compile Sources) — JS живёт строками в `Scripts.swift`.
- **Установка на телефон:** iloader (Windows) с бесплатным Apple ID, подпись живёт 7 дней. Sideloadly с конца октября 2026 не работает (ошибка Apple -80046).
- **Продление (с 27.10.2026):** владелец перешёл на SideStore (установлен через iloader) + LocalDevVPN из App Store; вход в Apple ID в SideStore заработал после выбора anisette-сервера «SideStore (New)» и Reset adi.pb. Fon ставится в SideStore через «+» из скачанного IPA; автопродление — автоматизация «Команд» (Refresh All). Fon стоит и на устройствах семьи — у каждого нужен свой SideStore.
- Проверить на настоящем айфоне можно только руками владельца — проси скриншоты и описание поведения.
- Логи GitHub Actions могут быть недоступны для чтения из облачной сессии; при ошибке сборки проси владельца скопировать текст ошибки.

| `Fon/MainViewController.swift` | Лента: **свой WKWebView на каждую вкладку** (создаётся лениво, не перезагружается при переключении; повторное нажатие — наверх, затем к корню). Вкладки «Поиск» на панели нет: поиск — отдельное место в той же области (`searchTabIndex = tabs.count`), открывается лупой в шапке YouTube или лупой на подборках. В режиме музыки «Главная» → нативные подборки `MusicHomeViewController` (лента YouTube с чипом «Музыка» — по карточке, флаг `musicFeedShown`; повторное нажатие «Главной» возвращает к подборкам), «Вы» → «Медиатека» (`LibraryViewController`); оба — `UINavigationController` дочерними VC в `browseContainer`. Перемешивание/очередь из своих треков — `/watch_videos?video_ids=…` (до 50 id). `PlayerView` поверх; уход в фон, прерывания (звонки) |

| `Fon/PlayerView.swift` | Отдельный WKWebView со страницей `/watch`. Режимы: мини-полоска (64pt над вкладками) и развёрнутый. В режиме музыки развёрнутый = нативный `MusicPlayerView` поверх веб-плеера (webview играет под ним); кнопка «список» показывает страницу YouTube, ♪ — назад к плееру. В режиме видео: шапка с ♡ (сохраняет видео в «Понравившиеся» режима музыки — облачный плейлист), PiP и ♪. Свайп вниз по видео/обложке (`UIPanGestureRecognizer`, плеер едет за пальцем) сворачивает; в полном экране — выходит из него (видео тоже едет за пальцем с сопротивлением). Мини-полоска тянется вверх за пальцем. Плавность (просьба владельца): скорость пальца при отпускании (`takeReleaseVelocity`) передаётся пружине `setPlayerState(_:velocity:)` (0,5 с, damping 0,86), возврат на место — пружиной со скоростью пальца, сопротивление как у прокрутки iOS (`rubberBand`) |
| `Fon/MusicPlayerView.swift` | Плеер в стиле Spotify: обложка **как есть** (`ArtworkLoader` размер `.player`: квадрат альбома или кадр 16:9 без полей — владелец попросил убрать чёрные рамки),  градиент под её средний цвет, ♡ (облако), ползунок (плавно интерполируется между сообщениями раз в 1 с), prev/play/next, повтор трека (`video.loop`) |
| `Fon/Library.swift` | `Library` — история «Недавно слушали» (JSON в Application Support, до 100; трек записывается после 20 с игры в режиме музыки — сообщение `played`, в т.ч. в фоне) и старые локальные лайки до переноса в облако; `YouTubeLinks` (watch/mix `RD<id>`/«Мой микс» `RDMM`/queue `watch_videos`); `ArtworkLoader` — квадратные обложки из `i.ytimg.com` (maxres→sd→hq): кадр 16:9; если поля по бокам однотонные (обложка альбома в центре) — центральный квадрат, иначе картинка целиком + размытая копия сверху/снизу; средний цвет. `TrackTitle.clean` — «Исполнитель - Песня (Official Video)» → песня + исполнитель (в режиме музыки: плеер, мини-полоска, медиатека) |
| `Fon/LibraryViewController.swift` | Медиатека: «Понравившиеся» (облако) и «Недавно слушали»; `TrackListViewController` (слушать/перемешать, смахнуть — убрать; ♡ справа у каждого трека — в «Понравившиеся»/убрать, просьба владельца: добавлять прямо из истории). Свои плейлисты и ⊕ **убраны по просьбе владельца** (28.10.2026) |
| `Fon/CloudLikes.swift` | «Понравившиеся» = приватный плейлист **«Fon — музыка»** в аккаунте YouTube. Скрытое окно `m.youtube.com/robots.txt` (тот же вход в Google) + `callAsyncJavaScript` со `Scripts.cloud`: внутренний API YouTube (`playlist/get_add_to_playlist` — найти плейлист по названию, `playlist/create`, `browse/edit_playlist`, `browse VL<id>` + continuation) с `Authorization: SAPISIDHASH`. Контекст клиента берётся из `localStorage['fon-ctx']` (его сохраняет `common` с любой страницы YouTube). ♡ оптимистичный, при ошибке — откат и алерт. **Запросы идут строго по одному** (очередь в `CloudLikes.call`, аргументы считаются при запуске; одновременные обновления сливаются в одно; перенос старых лайков — один раз): в 1.29 параллельные обновления при старте создали два плейлиста «Fon — музыка». `list` каждый раз ищет плейлист по названию (лишний можно удалить в YouTube). Кэш списка обновляется при старте и возврате в приложение |
| `Fon/MusicHomeViewController.swift` | Экран режима музыки в стиле стриминга (compositional layout), `Kind`: **`.home`** — приветствие + быстрый доступ («Понравившиеся», «Мой микс», последние), затем **полки YouTube Music** аккаунта (`MusicFeed.shelves`: треки — ряды по 4 «Быстрый выбор», карточки миксов/альбомов, круглые исполнители), «Ещё → лента YouTube»; пока полки не загрузились или без сети — свои: «Миксы для вас» (Mix по исполнителям истории и лайков), «Недавно слушали», «Понравившиеся». **`.subscriptions`** (вкладка «Подписки» в режиме музыки, просьба владельца 28.10.2026) — исполнители из подписок (круглые, нажатие — радио исполнителя) и «Новое»: видео ленты подписок только этих исполнителей (очередь `watch_videos` с нажатого). ## Ключевые приёмы
- **Безопасная область (просьба владельца: «везде знать про чёлку»):** ничего управляемого под «чёлкой»/Dynamic Island и у полоски «домой». Полный экран — видео на весь экран (вариант 1.56 с `bounds.inset(by: safeAreaInsets)` уменьшал видео — владельцу не понравилось), а панель YouTube `#player-control-overlay` — внутри safe area: `PlayerView.sendSafeArea` → `__fon.setSafe` → CSS `--fon-safe-*`; развёрнутый плеер, мини-полоска и `browseContainer` — в пределах safe area слева/справа (альбомная ориентация). Шапки своих экранов уже отступают `safeAreaInsets.top`.
- **Системный плеер (AVPlayer)** — см. `NativeAudio.swift` в таблице: первая попытка (1.43–1.47) убрана, вторая (Safari для Mac → HLS) — в работе.
- **Видимость:** `document.hidden`/`visibilityState` всегда «visible», события `visibilitychange` перехватываются на window (capture) и не доходят до YouTube; настоящее состояние — `__fon.realHidden`.
- **Автопродолжение в фоне (как Brave `MediaBackgroundingScript.js`):** `HTMLMediaElement.prototype.pause/play` обёрнуты — пауза из JS **при видимой странице** = пауза пользователя (`__fonUserPaused`); в фоне пауза из JS YouTube не считается пользовательской (обычно это реакция на отказ WebKit), настоящая пауза в фоне — только наша команда (`fon.explicitPause` → `__fonHardPause`). Пауза без JS (от WebKit при сворачивании) + переход в hidden в пределах 2 с → вызываем оригинальный `play()`.
- **Старт в фоне (видео ещё грузилось при сворачивании):** без звука iOS усыпляет приложение и WebKit, видео не стартует. `PlayerView.watchBackgroundStart` держит `beginBackgroundTask` и зовёт `__fon.backgroundTick(first)` **сразу**, затем раз в 0,5 с (до 25 с; раньше первый вызов был через 1 с — отсюда пауза ~1 с при сворачивании) — вызов `evaluateJavaScript` будит WebKit, страница жмёт `play()`; следим все ~25 с фоновой задачи (стоп раньше — только 'idle', пауза пользователя); **в 1.52 отпускали после 3 тиков (~1 с) — пауза от iOS приходила позже, музыка останавливалась (жалоба владельца)**. **Смена трека в фоне:** за <6 с до конца трека (тик раз в 1 с) и на `ended` страница шлёт `{type:'trackEnding'}` → `MainViewController.keepAliveUntilPlaying()` (то же, что при сворачивании); `backgroundTick` не считает почти доигравший трек «playing», а если через 3 с после `ended` YouTube сам не переключил трек — жмёт `cmd('next')`. Отключение наушников (`routeChange .oldDeviceUnavailable`) → `markUserPaused`, чтобы не включить звук в динамик.
- **Своя громкость YouTube** (просьба владельца: музыку тише, чтобы слышать игру): ползунок под кнопками в `MusicPlayerView` → `Settings.youtubeVolume` → `NativeAudio.setVolume` (`AVPlayer.volume`). **Работает только у системного плеера** (проверено владельцем в 1.62 — музыка тише) — с веб-плеером ползунок скрыт. У веб-страницы на iPhone громкость не меняется ничем: `video.volume` заблокирован, Web Audio не берёт звук потока MediaSource (1.52), служебный `_setMediaVolumeForTesting:` WebKit не действует (1.56). Вариант «спрятать MediaSource, чтобы YouTube отдал простой поток, и пропустить его через Web Audio» владелец отклонил.
- **Звук при открытии:** плеер открывается не нажатием на его странице, поэтому YouTube считает это автозапуском и включает видео muted. В `player` на `playing`/`volumechange`/тик раз в секунду вызываем `movie_player.unMute()` + `video.muted=false` (WebKit позволяет — `mediaTypesRequiringUserActionForPlayback = []`). Если muted случился в пределах 1,5 с после касания страницы — это пользователь (`__fonUserMuted`), не трогаем. Не больше 5 включений за 10 с.
- **Экран блокировки:** Now Playing ведёт сам WebKit через `navigator.mediaSession`. `setActionHandler` перехвачен: наши play/pause/nexttrack/previoustrack/seekto, `seekforward/seekbackward = null`, YouTube их не перезапишет. Нативного `MPRemoteCommandCenter` нет — он конфликтовал с WebKit.
- **Лента → плеер:** клик по `a[href]` с путём `/watch` в ленте перехватывается и уходит в плеер (`{type:'open'}`); запасной путь — KVO на `url` ленты. В плеере ссылки не на `/watch` уходят в ленту (`{type:'browse'}`).
- **Мини-режим:** класс `fon-mini` на `<html>` растягивает `#player-container-id/.player-container/#player` и `video` на весь viewport; webview в мини-полоске 16:9.
- **Режим музыки / экономия:** класс `fon-music` прячет `video` (opacity 0) и показывает обложку `i.ytimg.com/vi/<id>/hqdefault.jpg`; качество — минимальное через `movie_player.setPlaybackQualityRange/setPlaybackQuality`. В фоне качество тоже падает до минимума (кроме PiP). YouTube запоминает качество в `localStorage['yt-player-quality']` — из-за этого 144p «прилипало»; теперь в режиме видео ключ стирается в начале документа, а после понижения качество явно ставится в hd720 (iPhone) / hd1080 (iPad). Чистый «только звук» в веб-плеере невозможен (протокол YouTube), это осознанный компромисс.
- **Режим музыки — контент:** видео открывается с Mix-плейлистом `&list=RD<id>` (похожая музыка, как радио в YT Music); под плеером скрыты комментарии и Shorts.
- **Свой полный экран:** m.youtube на iPhone включает системный AVKit-фулскрин (без субтитров YouTube и меню качества). В `player` подменены `webkitEnterFullscreen/requestFullscreen/exitFullscreen` и геттеры `fullscreenElement/fullscreenEnabled/webkitDisplayingFullscreen`: класс `fon-full` растягивает плеер на окно, шлются `webkitbeginfullscreen/fullscreenchange`, приложение получает `{type:'fullscreen'}` — прячет шапку и статус-бар, на iPhone поворачивает в landscape (`requestGeometryUpdate`), но вертикальное видео (`videoHeight > videoWidth`) оставляет в portrait. В полном экране качество не понижается и видео видно даже в режиме музыки. **Выход кнопкой YouTube** (жалоба владельца: «кнопка свернуть не работает» — YouTube снова просил «войти»): пока `fon.isFull`, нажатие на видимую кнопку полного экрана (`.fullscreen-icon` или aria-label «полноэкран…/fullscreen») перехватывается в capture-фазе (click; запасной путь — касание без сдвига, через 350 мс) → `setFull(false)`.
- **Пропадающая картинка видео (чёрный экран, звук идёт):** WebKit теряет слой видео после перестроек страницы (меню ⚙, поворот, выход из полного экрана). `fon.repaint()` убирает видео на 2 кадра (`display:none`) и возвращает, а на это время рядом с видео кладёт снимок текущего кадра (`canvas`), чтобы не было заметного мигания (жалоба владельца после 1.29); вызывается при смене полного экрана, возврате в приложение, повороте (`viewWillTransition`), а **только в полном экране** — по `MutationObserver` на class/style/детей `body` и class `html` (меню YouTube) и после `touchend` (в обычном плеере это мигало на каждое касание). После своей перерисовки 1,2 с мутации игнорируются (без зацикливания). В полном экране скрыта «Фоновая подсветка» (cinematics). Меню YouTube (`bottom-sheet-container` и др.) в полном экране подняты поверх плеера (z-index). Пока меню YouTube открыто (скрипт шлёт `{type:'menu', open}`; проверка на касаниях и при добавлении элементов, не чаще 4 раз/с), свайп вниз плеера выключен **только на самом меню** (скрипт шлёт `top` меню; меню считается открытым, лишь если оно сверху — `elementFromPoint`) — иначе, потянув меню ⚙, владелец выходил из полного экрана; а ложное «открыто» отключало свайп выхода совсем (жалоба владельца). После выхода из полного экрана повторный вход 1,5 с не принимается (YouTube мог сразу запросить его снова). **Субтитры** в полном экране — по центру ширины; в вертикальном полном экране (под видео ≥70 px) — сразу под картинкой (класс `fon-cap-below`, `--fon-cap-top`).
- **Главная в режиме музыки:** грузится `/#fon-music`; скрипт `browse` убирает хэш и нажимает чип «Music/Музыка» (`ytm-chip-cloud-chip-renderer`) — обычные рекомендации, но только музыка.
- Скрываем родную нижнюю панель m.youtube (`ytm-pivot-bar-renderer`).
- **Порядок в полном экране:** ряд «Нравится/Не нравится/Поделиться/Сохранить» и «Другие видео» наезжали на время и главу — `tidyFullscreen` (раз в 1 с в полном экране) ищет их по aria-label/тексту в `#player-control-overlay`/`#player-container-id` и вешает класс `fon-hidden-full` (скрыт только при `html.fon-full`).
- **Зависшая загрузка** (после долгой паузы в свёрнутом приложении крутился спиннер): сторож раз в 1 с — должно играть (`!paused` или состояние 3), а `currentTime` стоит: 6 с → `seekTo` на то же место, 12 с → `loadVideoById` с этой секунды, 20 с → перезагрузка страницы с `t=`.
- **Обложки:** при сбое сети (нет ответа) `ArtworkLoader` повторяет запрос ещё 2 раза через 1,5 с.
- **Кэш (просьба владельца — «не грузить заново»):** обложки — память (`NSCache`, 500) + диск `Caches/artwork` (имя — SHA1 ключа, JPEG; при запуске старше ~1500 файлов удаляются), одна загрузка на картинку (ожидающие ячейки ждут её); `URLCache.shared` 64 МБ / 512 МБ; «Понравившиеся» — `Caches/likes.json` (видны сразу при запуске); подборки — `Caches/music-feed.json`. Страницы YouTube кэширует сам WebKit (`WKWebsiteDataStore.default()`, размер не настраивается). **Видео кэшировать нельзя:** YouTube отдаёт поток кусками через MSE (googlevideo, свой протокол), WebKit их не хранит, а перехватить https-запросы в WKWebView невозможно.
- **Ссылки в плеере:** в основное окно уходят только каналы/поиск/плейлисты/ленты (`BROWSE_PATH` в `player`); остальное (ответы в комментариях и т. п.) YouTube обрабатывает сам — владелец жаловался, что «Другие ответы» не открывались.
- **Обложки в карточках** — центральный квадрат кадра (без полей; размытый фон убран); в плеере — кадр 16:9 целиком. Ячейки запоминают ключ картинки ДО загрузки (картинка из кэша приходит синхронно — иначе «Мой микс» и др. оставались пустыми).
- **Shorts скрыты везде** (`common`): CSS по `ytm-reel-shelf-renderer`/`ytm-shorts-lockup-view-model*`/карточкам со ссылкой `/shorts/` (правила с `:has()` — отдельным блоком) + раз в 1,5 с прячем секции с заголовком «Shorts» и чип «Shorts».
- **Свой плейлист закончился** — YouTube включает похожее; `PlayerView.queueIDs` замечает id не из очереди и меняет «Играет из» на «Похожие треки».

## Как работать
0. **Не собирать без команды (с 28.10.2026):** правки коммитить и пушить только в рабочую ветку `claude/…`; в `main` (= сборка и новая версия в SideStore) — только когда владелец скажет «собирай». Тогда все накопленные правки уходят одной версией. **Отдельную проверку компиляции на ветке (`workflow_dispatch`) после каждой правки НЕ запускать** (просьба владельца 29.10.2026): код проверит сборка по «собирай»; если она упадёт — исправить и собрать снова. JS по-прежнему проверять локально `node --check`.
1. Правки → проверка JS: вырезать строки из `Scripts.swift` и прогнать `node --check`; логику можно гонять в jsdom со стабами `play/pause/visibilityState/mediaSession`.
2. Коммит и push в `main` → дождаться зелёной сборки в Actions → дать владельцу ссылку на run (Artifacts → Fon-ipa).
3. Владелец ставит через iloader поверх старой версии и присылает результат.
